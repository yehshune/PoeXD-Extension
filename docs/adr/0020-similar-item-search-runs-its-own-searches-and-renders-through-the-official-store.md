# Similar Item Search runs its own Trade searches and renders each batch through the official store

Players looking at a rare item want listings like it, not the exact item: the same stats they care about at or near its values, regardless of whether a stat came from a crafted, fractured or regular modifier. Today they rebuild such a search by hand, and one hand-made search rarely finds the right items: a search returns at most 100 ids sorted by price, each `/fetch` returns 10 items, and loosening one condition either finds nothing or floods the list with cheap near misses. Competing tools either leave the trade site (Almost runs about 30 seconds of searches through its extension and ranks them on its own server) or are desktop overlays. We add **Similar Item Search (找相似)**: from a rare item on the trade page, the user tunes a Similar Search Draft and PoeXD runs a short, bounded series of searches with the user's own session and shows the results in the official result list.

Verified on 2026-11-27 against the international PoE 1 site (Covens) through `pnpm poe`. PoE 2 is assumed to behave the same, since its Trade API shares the code paths:

- **Weighted sort works.** A `weight` stat group with `sort: { "statgroup.0": "desc" }` returns results in strictly descending weighted sum, and fractional weights such as `1/60` are accepted. `statgroup.N` counts **weight groups only**, from 0: with `[count, weight]` `statgroup.0` sorts by the weight group, with `[weight, weight]` and `[weight, count, weight]` `statgroup.1` sorts by the second weight group, and `statgroup.1` with a single weight group returns HTTP 400 `Unknown sort key`. Whether `weight2` counts toward N is not verified.
- **Sorting a clipped search is not global.** When `total` is 10000 the sort runs only over the clipped subset. The same ring query had a best weighted sum of about 235 unbounded, while a weight group `min: 180` (total 4586) returned ten results between 333 and 382. Path of Building's `SearchWithQueryWeightAdjusted` handles this the same way: it raises the weight minimum until the search is no longer clipped.
- **Weighted sums overrate lopsided items.** `weight` and `weight2` both put an item with 235 life and no resistances first in a life + fire + cold query, and a count gate does not change that. `max` inside a weight group filters items out instead of capping their contribution.
- **`/fetch` returns the score.** For a weighted search, `item.pseudoMods` carries `"Sum: X"`, the item's weighted sum.
- **`explicit.stat_X` matches crafted and fractured modifiers of the same stat.** `and[explicit life, fractured life]` returned 2,800 rings whose only life line is fractured, and `and[explicit life, crafted life]` returned rings whose only life line is crafted. Whether PoE 2 `desecrated` modifiers are covered is not verified.
- **The search rate limit** (`trade-search-request-limit`) is Account 3/5s and Ip 8/10s, 15/60s, 60/300s, 600/10800s.
- **The official store can render results it did not fetch, on a normal search page.** `addSearchQuery` with a synthetic search (`live: false`, `status: false`), `setSearchActive`, then `addSearchResult` with `result` in our order and `items` already filled renders full official rows in that order: Travel to Hideout, Market Translation, converted price and PoeXD's pin button all appear. The URL does not change and no API request is made. Switching back to the user's search with `setSearchActive` and forth again also makes no request and keeps the original batch (100 ids, 10 loaded items). When the user presses the official Search button while a synthetic search is active, the official app creates a new search that **replaces** the active synthetic one.

## Decision

1. **Scope.** Similar Item Search is offered for rare weapons, armour, accessories and jewels from the result row hover toolbar (search page and LiveSearch Primary Page), Pinned Items and the Result Board. Uniques, flasks, maps, gems and currency are out of scope. The PoB shopping list keeps its own search and only moves onto the shared draft component.
2. **A Similar Search Draft is not stored.** It is derived from the Source Item and lives until the panel closes, so ADR-0008 holds. Only the tolerance, base-or-category choice and default weapon mode are Preferences. The PoB shopping list keeps storing its per-entry selections as before.
3. **The draft searches stats, not modifier types.** Every crafted, fractured or regular line becomes `explicit.stat_X` by default; a line can be narrowed to "fractured only" or "crafted only". Each line is **Required** (`and` group), **Reference** (weight group) or **Ignored**. Defaults: tier 1–3 lines and crafted lines are Reference, other lines and enchantments are Ignored, and nothing is Required until the user locks it. Single resistances, attributes and life merge into pseudo totals, implicits included, and hybrid lines are split into their stats, with hybrid resistances and attributes covered by the pseudo totals as Path of Building does. Weapons add one of total DPS, physical DPS, elemental DPS or damage per hit, chosen from the item and switchable, with attack speed and critical chance off by default. Armour adds the armour, evasion, energy shield and ward the item has. One tolerance (default 80%) sets every minimum, and a line the user edits stops following it. Item level, sockets, links, corruption, influence and mirrored are not carried over. The listing status follows the page, else instant buyout.
4. **The query.** `stats[0]` is the weight group of Reference stats with weight `1 / target`, sorted by `statgroup.0` descending. `stats[1]` is the `and` group of Required stats. Weapon and armour properties are filter minimums. The query respects the 200 complexity budget (54 for the weight group, 4 per stat, 3 per other filter) by dropping the least important Reference stats, and tells the user.
5. **Searches run in the page, only when the user starts them, and are bounded.** They are same-origin requests from the trade page carrying the user's session, like Travel to Hideout, never from the Background. The **strict** search requires every Reference stat at its minimum and ends the run when it finds at least 10 results. Otherwise the **relaxed** searches keep the Required stats and property minimums, drop the per-stat minimums of Reference stats, and move the weight group minimum until 10 ≤ total < 10000, always raising it when the search is clipped. A run makes at most 4 searches and fetches at most 20 items, deduplicated by id. One search gate paces every request by the `x-rate-limit-*` state; a 429 stops the run and keeps what was found. Pressing the official Search button ends the run.
6. **Each batch is rendered by the official result list.** The strict search, each relaxed search, and an "all, by Similarity" batch are each a synthetic search in the official store. The panel holds the draft, the progress and one tab per batch; switching tabs calls `setSearchActive`. "Back to my search", or closing the panel, makes the user's search active again and removes the synthetic searches. Every fetched item is written to the `TradeResultCache`, so pinning, PoB copy and external links work on these rows, and pinning captures the official card as usual.
7. **Similarity is computed locally.** For each Reference stat and property, take `min(actual / target, 1)`; Similarity is their mean, with equal shares, so going past a target earns nothing and a miss costs. Required stats are excluded since every result meets them. While a synthetic search is shown, each line gets a met / within tolerance / missing mark and each row a Similarity badge, injected like the existing mod highlighting. A price-aware ordering is offered only where prices can be converted.
8. **The Result Board ignores Similar Item Search.** Its requests are marked so the board does not take a Similar Item Search fetch as a new search. ADR-0018 still holds: the board covers one official search and reads official rows only.

## Considered Options

- **Open the final query in the official page and let it fetch**: rejected. It costs an extra search per batch, offers one batch at a time, and leaves no place for Similarity ordering.
- **List results inside the panel**: replaced by Decision 6. Rows rendered by the official store keep every official action and every result enhancement, and pins keep their official card snapshot.
- **One relaxed count search (`count ≥ N − 1`)**: rejected. Sorted by price it surfaces cheap near misses first and needs many fetches to reach the close ones; sorted by weight but clipped it is not the global best.
- **Rank on the server only (weighted sum)**: rejected as the final order because of lopsided items; kept for picking candidates.
- **Cap contributions with `max` in the weight group**: rejected; it removes better items instead of capping them.
- **Weights from build calculations, as Path of Building does**: out of scope. That answers "what improves my build", not "what is like this item".
- **Run the searches in the Background**: rejected. All entry points are on the trade page, and same-origin requests carry the session without new permissions.
- **Suggest replacing crafted lines or require open affixes** (buy a base and craft the rest): deferred. The Trade site supports `pseudo.pseudo_number_of_empty_prefix_mods`, `pseudo.pseudo_number_of_empty_suffix_mods` and `pseudo.pseudo_number_of_crafted_mods` on both games, but deciding which lines can be traded for an open affix needs its own algorithm.

## Consequences

- PoeXD sends Trade searches the official site would not have sent, which `PRIVACY.md` does not cover today. Its Network requests row for the official trade sites (English and 繁體中文) must say that searches and fetches built from an item are sent with the user's session only when the user starts Similar Item Search, in the same change that ships the feature. No new host permission is needed.
- The official store mutations `addSearchQuery`, `setSearchActive`, `addSearchResult`, `setItemForSearchResult` and `removeCurrentSearch` become coupling points on normal pages too, as they already are in the LiveSearch Primary Page.
- A run uses the user's search budget. Four searches can delay a manual search by a few seconds, and the run stops rather than compete.
- Hideout tokens expire about 5 minutes after `/fetch` (ADR-0017). Rows of an older batch need their token refreshed from the batch's search ID before Travel to Hideout, or the user is asked to search again.
- `utils/pob-entry-search` becomes a shared draft that takes either a PoB item or an official item JSON (read through `utils/trade-item-mods.ts`).
- Still to verify in PoE 2: `desecrated` coverage by `explicit.stat_X`, and the same sort and clipping behaviour.
