# Realm-independent bookmarks with Auto league and TFT-compatible transfer

Bookmarks used to open exactly the URL they were saved with, including its realm host and league. Because the Tencent realm (`poe.game.qq.com`) uses different league names from the international realm, "replace league for all bookmarks" fetched leagues from whichever realm the user was on and rewrote every bookmark to them, which broke bookmarks meant for the other realm.

## Decision

1. **Realm registry.** `utils/trade-realms.ts` is now the only place that decides which official Trade hosts are supported: international `*.pathofexile.com` (language subdomains included), Taiwan `pathofexile.tw` and Tencent `poe.game.qq.com`. Content-script matches, `tabs.query` patterns and host checks all read from it. Korean realms (Kakao and Daum) are deliberately out of scope.
2. **Bookmarks do not store a realm.** At open time a bookmark's stored Search Record URL is rewritten to the current page's origin (`resolveBookmarkUrl`). The stored URL keeps its original host as canonical data.
3. **Auto league by default.** A bookmark placement may carry `leaguePinned: true`. Without it the bookmark is **Auto**: when it is opened, and in the LiveSearch console, it follows the current page or console league. When no league is known it falls back to the recorded league. "Replace league" now offers an **Auto** option that only clears `leaguePinned` and never rewrites Search Records. Choosing a concrete league rewrites the Search Record (as before) and pins it. Existing bookmarks have no flag, so they become Auto with no data migration.
4. **TFT-compatible Bookmark Transfer.** Share codes are now the same format as TFT Trade Extension: `Base64(UTF-8(JSON.stringify({ folders })))`, with standard Base64, `=` padding kept and no prefix. Folders are a flat list using `parentId`/`depth`/`childIds`/`index`. Bookmarks are `{ id, name, league: "Auto" | <league>, poeVersion: "Poe1" | "Poe2", endpoint, type: "search" | "exchange", idx, isDone }`. PoeXD adds an optional `coverImageUrl` on each bookmark and a top-level `poexd: { scope, gameVersion }` hint so a round trip keeps the export scope. TFT ignores both fields. Importing a TFT code keeps only the bookmarks for the current game version. The downloaded backup file holds the same JSON. Legacy `poexd-bm1:` / `poexd-bm2:` codes and legacy PoeXD JSON files are no longer accepted. The PoeXD desktop app uses the same format, so codes move freely between PoeXD, the extension and TFT. Better Trading codes are also detected automatically and import-only: `3:` / `2:` / unprefixed v1 folder codes and its multi-line backup file (active and archived sections). Better Trading stores no league, so its bookmarks import as Auto league; folder icons are dropped. Detection is unambiguous because an unprefixed code is only treated as Better Trading when it decodes to `{ tit, trs }`, while TFT decodes to `{ folders }`.

## Consequences

- Search Record identity still includes the league, so history and Resume Plans are unchanged. Auto bookmarks are deduplicated on import by game version and search ID only.
- TFT exports carry no stable IDs, so PoeXD creates fresh IDs on every export. Importing the same PoeXD code into TFT twice therefore creates duplicates there.
- Old `searchId` short codes are stored per realm server, so they may not resolve on another realm. Gzip query hashes do work across realms.
- Known limitation: a gzip query hash contains the query JSON itself, and its `name`/`type` fields are written in the realm's language (English, Traditional Chinese, Simplified Chinese, and probably the language subdomains too). Stat IDs and filter options are the same in every realm. A bookmark that searches by item name therefore only works in a realm of the same language. Fixing this (open on the original realm, or translate the names) is deferred.
