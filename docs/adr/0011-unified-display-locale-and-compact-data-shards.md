# Unified Display Locale, Zero-Dependency Reactive i18n, and Compact Game Data Shards

We unify the previously separate affix locale setting (`affixDisplayLocale`) into a single global **Display Locale** Preference (`displayLocale`, placed in `GLOBAL_PREFERENCE_NAMES` alongside `theme` and migrated from legacy `affixDisplayLocale_poe2` / `affixDisplayLocale_poe1`) that drives both extension UI copy (`zh-TW`, `zh-CN`, `en`, with the other 8 supported affix locales falling back to `en` for UI text) and all game-domain dictionaries (affix stats, item names, item categories, affinity labels, and non-stat Trade filter labels). For runtime UI translation across Vue components, injected DOM controls, standalone extension pages (`popup`), and Background service worker error/status fallbacks, we use a lightweight, zero-dependency, type-safe reactive TypeScript i18n module rather than `chrome.i18n` (which cannot switch locales at runtime) or a heavy runtime library (keeping `public/_locales/*/messages.json` strictly for static browser Manifest metadata). Simultaneously, we replace the legacy 1.88 MB `public/json/{poe1|poe2}/items_translate.json` (which duplicated unused CDN icon URLs and only mapped English to Traditional Chinese) and the redundant dual-alias category keys in `components/sidebar/typeMaps.ts` with canonical gear-type keys and compact, icon-free per-locale data shards generated by `poexd-data` from official `.datc64` tables (`BaseItemTypes`, `Words`, `ItemClasses`), alongside localized `trade-filters` shards.

## Considered Options

- **Keep UI Locale and Affix Display Locale as separate preferences**: rejected; a single `displayLocale` (`auto` + 11 locales) covers both with less cognitive load, while fallback queries typed into the official Trade search input continue to use the **Page Locale** so official search matching never breaks.
- **Keep `displayLocale` scoped per game version (`poe1` / `poe2`)**: rejected; standalone extension pages such as `popup` have no bound game version, and `auto` already adapts dynamically per Trade tab host/locale.
- **Use `chrome.i18n` / `@wxt-dev/i18n` or `vue-i18n` runtime**: rejected; `chrome.i18n` is locked to the browser's startup UI language and cannot react to in-extension preference changes or Trade realm auto-detection, while a 50-line reactive TypeScript dictionary helper provides compile-time key checking, zero bundle overhead, and zero CSP `unsafe-eval` risk across Vue, DOM, and MV3 Service Worker contexts.
- **Keep `items_translate.json` and dual-language parenthetical labels (`胸甲 (Body Armour)`) in `typeMaps.ts`**: rejected; `items_translate.json` wasted >85% of its 1.88 MB payload on unused `icon` URLs and lacked `zh-CN` and reverse-lookup support, while parenthetical bilingual labels cluttered the UI once full locale switching is available.

## Consequences

- `Preferences` replaces per-version `affixDisplayLocale` with global `displayLocale` (migrating existing stored values on initialization).
- `poexd-data` normalizes gear-type keys (eliminating singular/plural and hyphen/underscore duplicates such as `claw`/`claws` and `urn-relic`/`urn_relic`) and emits compact localized item/category shards without icon URLs, reducing item dictionary size by over 90%.
- Category and affinity labels render cleanly in the active Display Locale without parenthetical bilingual suffixes, and Background-to-UI error/status payloads prefer structured codes rendered via `t()` at the UI boundary.
