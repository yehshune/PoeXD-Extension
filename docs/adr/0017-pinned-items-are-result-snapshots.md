# Pinned Items are result snapshots rendered with the official card classes

Users want to keep a few Trade results to come back to and compare, above all in the LiveSearch Primary Page, where results keep arriving and older rows fall off the display cap (issue #12). We add **Pinned Items (釘選物品)**: a pin button in the result row's hover toolbar saves a snapshot, and a Sidebar pane lists the snapshots as cards styled like official results.

Verified on 2026-11-18 against the international PoE 1 site over CDP:

- An official `/fetch` result is `{ id, listing, item }`. An instant buyout listing (`status: securable`) has `hideout_token` and `fee` but no `whisper`. A regular listing has `whisper` and `whisper_token`. The whisper text is written in the seller's language.
- Both tokens are JWTs whose payload carries `exp`. A token is valid for about 5 minutes after `/fetch` returns it. `/fetch` returns a `hideout_token` only when it is called with a valid `query` (search ID). Without one, the item comes back without a token. An unknown or removed item comes back as `null`.
- The official Travel to Hideout button calls `POST /api/trade/whisper` with `{ token }`. `success: false` means the item is in demand, and clicking again sends `{ token, continue: true }`. Error `code 1` (HTTP 404, "Item no longer available") means the item is sold, and the official page marks the card as gone. A sold item is still returned by `/fetch` with its `hideout_token`, plus a top-level `gone: true`, so it must be treated as sold before any whisper is sent. Verified live with an account that was not in game: the whisper for a live item returns HTTP 400 `code 2` ("Your account must be in-game"), and the endpoint is limited per account (15/60s, 75/600s, 300/3600s, 900/21600s).
- Official result styling is scoped by `#trade …` and `.results …`, and the stylesheet file names carry a hash.
- Market Translation translates result rows in the DOM only, so `/fetch` JSON stays in the realm's own language (ADR-0012).

## Decision

1. **A Pinned Item is a result, not criteria.** It stores a whitelisted copy of the item JSON and listing, plus realm, league, source search ID and page locale. It stores no Trade query criteria, so ADR-0004 and ADR-0008 still hold. The source search ID is only used to reopen the search and to refetch the item.
2. **No tokens are stored.** `hideout_token` and `whisper_token` stay in memory in the page's result cache. When the user clicks Travel to Hideout, we first distinguish refreshing an expired token via `/fetch/{id}?query={source search}` (`refreshing`) from dispatching `POST /api/trade/whisper` (`traveling`). We do not retry, schedule or batch it. A confirmed sold outcome (`null` or `gone: true` from `/fetch`, or error `code 1` from `/whisper`) permanently marks `sold: true` on the stored snapshot via `mark-sold` so Travel to Hideout stays disabled across reloads until re-pinned or cleared via `clear-sold`. An item without a token asks the user to reopen the source search.
3. **Realm-bound actions.** Whisper and Travel to Hideout are disabled when the current page is on another realm (ADR-0007 makes Bookmarks realm-independent, but listings are not). The source search opens on the realm the item was pinned from.
4. **Background-owned storage.** Snapshots live in `chrome.storage.local` under `poexdPinnedItemsV1_<version>`, at most 50 per game version. The Background serializes writes (`pin`, `unpin`, `reorder`, `clear`, `mark-sold`, `clear-sold`) and re-validates every snapshot. Pages read storage directly and follow `storage.onChanged`. At the limit, new pins are rejected with a notice instead of dropping the oldest; re-pinning an existing id replaces its snapshot and clears `sold`. Pinned Items are local only and are not part of Bookmark Transfer.
5. **Cards are a sanitized snapshot of the official card, in their own shadow root.** When the user pins, we copy the official icon area (`.left .newItemContainer`) and item frame (`.middle` children) of the result row into a JSON node tree. Only allowlisted tags are kept (`div`, `span`, `br`, `hr`, `img`, `small` and a few inline tags), with only legal class tokens (our own `poexd-*` tokens removed, and nodes that only carry them dropped), `data-field`, `title`, an inline `color`, and `img` sources on the official CDN. Node count, depth and serialized size are capped; an oversized card is not stored. The same sanitizer runs on capture and when reading storage, and the Sidebar rebuilds the card with `createElement` and `textContent`, never by parsing HTML. Each card sits in a nested shadow root that links the official stylesheets found in `document.styleSheets` at runtime, so sockets, influence symbols, mod ranges and the PoE 1 / PoE 2 headers look exactly like the official card. Pins without a snapshot (made before this change, or when the row could not be captured) fall back to a card drawn from the item JSON with official class names. The snapshot keeps the language of the page at pin time; an English snapshot is still translated by Market Translation through a request event, because its markup is the official markup. The card is shown only when the user expands a pin; the price shows the currency icon read from the result row at pin time.
6. **The pane is ordered by the user.** Pins are drag-sorted; dropping a pin on the drag trash zone unpins it. Collapsed, a pin is a compact row with a larger 40px icon (icon, name in its rarity colour, age and cross-league/realm tags without redundant buyout or seller account clutter, price with currency icon on the right), and its hover actions (travel/whisper, open source, and `⋯` menu containing PoB copy and unpin) appear on hover or open menu (not on keyboard focus alone). Clicking the row replaces the collapsed summary row with a two-column header (normalized 88px framed icon on the left; price, converted price with currency icon when `enablePriceComparison` is enabled, gold fee with coin icon when present, pinned timestamp, age/seller metadata, collapse button, and the full action bar with `secondary` main action and direct PoB copy on the right) above the expanded card snapshot (with inline centered mods and left-aligned mod numerical ranges); a press-and-move starts a drag instead. Unpinning is in the row menu. A clear menu offers direct clearing of sold items (`clear-sold`) and confirmation-gated clearing of the visible league or all pins (`clear`). The Background stores the order with a `reorder` command that carries only the ids the user could see: those pins take each other's slots and pins hidden by the league filter stay where they were.
7. **One result cache per page.** Official fetch responses (MAIN-world interception) and the console's own `/fetch` results feed one in-memory `TradeResultCache`. PoB copy, external links and pinning read from it, so the console gets PoB copy data too.

## Considered Options

- **Clone the official `.row` DOM as live nodes**: rejected. Official Vue handlers (whisper, travel) stop working, PoeXD's injected buttons get cloned along, and live nodes cannot be persisted across reloads. A sanitized node-tree snapshot of the item part only (Decision 5) avoids all three.
- **Draw the card from JSON only**: replaced by Decision 5. It lost sockets, influence symbols, mod ranges and the PoE 1 / PoE 2 header differences, and every official change had to be followed by hand.
- **Render with the official Vue component**: not possible on normal pages. The official app renders only the active search, and the console can do it only because it takes over the whole page.
- **Store the token with the snapshot**: rejected. It expires in about 5 minutes and is bound to the search, so a stored copy is useless and only widens what we keep.
- **Write storage from each tab**: rejected. Two tabs pinning at once would overwrite each other with read-modify-write.
- **Drop the oldest pin at the limit**: rejected. Pins are deliberate, so silently removing one is surprising.

## Consequences

- Official class names and the whisper endpoint become coupling points, like the existing result enhancements.
- The whisper gate never retries on 429. The response when the user is signed out is not verified yet.
- A card snapshot is frozen in the language and official markup of the day it was pinned. Old snapshots may look slightly off after an official CSS change.
- Phase 2 (side-by-side comparison) can align mods by `extended.hashes`, which the whitelist keeps.
