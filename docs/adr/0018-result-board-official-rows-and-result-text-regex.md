# Result Board reads official result rows only, and Stash Search Regex uses the result's own text

Players want the results of one Trade search gathered in the Sidebar so they can filter, sort and group them, above all to find a Seller who holds several of the results they want and buy them in one hideout visit. Today almost every listing is instant buyout, so the useful follow-up is not a whisper but text that lights up the chosen items in that Seller's stash. We add the **Result Board (搜尋結果看板)** and the **Stash Search Regex (倉庫搜尋 regex)**.

Observed on 2026-11-19 against the international PoE 1 site over CDP: a search lists at most 100 result ids ("Showing 100 results (10000+ matched)"), the official page fetches them 10 at a time, and further batches are fetched only through its own "load more" button. Official fetch responses already feed PoeXD's in-memory `TradeResultCache` (ADR-0017).

## Decision

1. **The board only shows official result rows.** "Load more" and "load all" on the board drive the official page's own "load more" one batch at a time, waiting for each official fetch to finish (plus a short pause) and stopping on an error or rate limit, at 100 results, when the button disappears, when the user stops, or when the search changes. PoeXD never calls `/fetch` for the board itself. Every board entry is therefore also an official row, so locating and highlighting it always works, and the existing result enhancements (converted price, mod highlight, Market Translation) apply to it unchanged.
2. **The board does not reorder or mutate the official list by default.** Its filters and sorting live in the Sidebar only, keeping the official rows' order intact. When a board filter is active, the user may explicitly opt in to temporarily hide non-matching official rows via CSS only (never reordering DOM nodes); while active, a prominent banner with a one-click "Show all" reset is shown above the results, newly fetched rows automatically adopt the filter, and the state resets automatically on a new search.
3. **Stash Search Regex is written from the result's own item data.** It uses the text the realm's `/fetch` returned (which Market Translation never changes, ADR-0012), never the Display Locale, so it needs no game-data lookup and no extra Preference. Confirmed in game on 2026-11-20: on a localized client the stash search still matches English item names, base types and the price note (for example `~b/o 2 chaos`), but not English mod or property text, so the regex uses only those three; a separate Game Client Language Preference remains the fallback if this stops holding. The search length limit is 250 characters on both PoE 1 and PoE 2. One regex aims to light up every result the user picked from that Seller at once. It is written as a name group, a base type group and a price group (`"name1|name2" "base1|base2" "price1|price2"`) that must all match. The stash search has no "or" across quoted terms, so names, bases and prices are matched independently and cross combinations (name of one pick with the price of another) can also light up; the base group narrows them, and the regex is checked against the Seller's other retrieved results so any that would also light up are reported as indistinguishable. A single paste is preferred over precision: over the limit it first merges price prefixes, then shortens names, then drops the base group, and only then splits, with each part restored to the most precise form that fits. Exact per-item matching in one paste (`name.*price`) depends on whether the game matches across lines, which is still to be confirmed in game. It includes the listed price, written the way the Trade site writes it, because the Seller's stash holds many items the board never saw; only when the game's length limit is exceeded is it shortened first and then split into parts.

## Considered Options

- **The board calls `/fetch` itself through PoeXD's rate gate**: rejected. Results fetched that way have no official row, so they cannot be located, they miss every result enhancement, and PoeXD would compete with the official page for the same per-account fetch budget. The cost of the chosen option is a dependency on the official "load more" button, which the result sort controller already has.
- **Regex in the Display Locale**: rejected. It would be wrong for everyone who reads the site in Chinese but plays on the international client.
- **A Game Client Language Preference with Game Wording from poexd-data**: deferred. It costs a data dependency and a setting; the result's own text is enough unless in-game testing shows otherwise.
- **Bulk whisper text for one Seller**: rejected. Instant buyout made it rarely useful.

_Note (ADR-0020): Similar Item Search fetches results itself and shows them as synthetic searches in the official list. The board ignores those requests, so this decision is unchanged._
