# Path of Exile Trade Assistance

This context helps players retain, understand, and reuse searches performed on the Path of Exile Trade site.

## Language

**Search Record**:
A retained representation of one Trade search, identified by game version, league, and canonical search ID. It contains descriptive metadata shared by history and bookmarks. It does not store Trade query criteria separately: the canonical search ID is a gzip query hash that encodes the criteria, so the search ID is their single source of truth and features decode it on demand. See ADR-0008.
_Avoid_: Search payload, cached query

**Legacy Search ID**:
A short, server-issued search ID that is not a gzip query hash. The official Trade site no longer resolves these (they open an empty search), so a Search Record or Bookmark that holds one is **invalid**: it is kept and shown as invalid until the user removes it, and it is skipped on Bookmark Transfer import.
_Avoid_: Short code, old search ID

**Bookmark**:
A user-named, durable reference to a Search Record that may be organized into a bookmark group. It is realm-independent: it always opens on the current official Trade host. Its league is **Auto** by default (follows the current page / console league) unless it is pinned to a league (`leaguePinned`). A Bookmark is added in one action with no dialog; the official search form is first written through to the URL, so the stored search ID always encodes what the form showed at that moment, and if that write-through fails the Bookmark is not added.
_Avoid_: Saved Search Record

**Stat Group Template (User-facing: 常用詞綴群組)**:
A user-named, durable bundle of one or more stat groups (each with its group type, count/weight value, and stat filters) that the user treats as one reusable category, for example "life + resistances + movement speed". It holds no other criteria (item, listing status, or non-stat filter fields). It is captured from the stat groups on the current official search form, after the user confirms which of them to keep, and is stored as-is (no duplicate detection). It is game-version-specific but independent of realm and league, lives only on the local device, is never part of Bookmark Transfer, and is kept as one flat, user-ordered list managed in its own Sidebar pane. It is used through the official "add stat group" entry, where choosing one overlays its stat groups onto the current search.
_Avoid_: Filter Preset, 常用篩選, Saved Group, affix package (詞綴套件), filter bookmark

**Mercenary Skill Group (User-facing: 傭兵技能群組)**:
A PoE 1 official stat group of type `mercenary` that describes one Mercenary Warrant skill and the supports linked to it; its `min` is how many of those entries must match. Supports of one family (Lesser / normal / Greater) never coexist on a skill, so "this family at tier N or higher" is expressed by putting every qualifying tier's id in the same group. It is edited through the Mercenary Picker (傭兵技能選擇器) instead of the affix selector: opened from a group's own button, the picker replaces that one group; opened from the batch entry next to the Stat Group Template button, it appends one group per checked skill (optionally plus a `not` group excluding the build's weak skills), or a single `and` / `not` / `count` group over the checked skills. On a mercenary search (Warrant item type, or the form already holds mercenary entries), `and` / `not` / `count` / `if` groups also get a mercenary button that writes the checked skills into that group in place, keeping its other entries. The group only counts matches, so the skill itself is not guaranteed when fewer supports are required than checked; the picker then adds the skill to an `and` group by default. Both are undoable like a Criteria Overlay and can also set the Warrant's build as the item type. Instead of capping how many supports may be picked, the user sets how many of the picked supports must match, with hints based on the skill's link tier (high 5–6, medium 3–4, low 2–3 links). Mercenary data (build skill pools, per-skill supports, support tiers) comes from game data via poexd-data, not from the stat dictionary.
_Avoid_: Mercenary affix, mercenary mod

**Criteria Overlay (User-facing: 疊加套用)**:
Adding criteria to the search currently on the page instead of opening a new one. Stats are only ever overlaid as whole stat groups (one group, or every stat group at once), never as single stats; other fields overwrite only the fields being overlaid and everything else on the page is kept. It never starts a search, and only the most recent overlay can be undone. Sources are a Stat Group Template or the Search Preview of a Bookmark or History Entry.
_Avoid_: Apply preset, merge search

**Search Preview (User-facing: 搜尋預覽)**:
The expandable view of the criteria a Bookmark or History Entry's search ID encodes, decoded on demand. It is toggled open explicitly rather than shown on hover, and from it criteria can be overlaid onto the current search when the page has an official search form. Whether a left click on a Bookmark or History Entry opens its search or toggles its Search Preview is a Preference; the other action stays available as a row button.
_Avoid_: Hover tooltip, item preview

**Bookmark Transfer**:
A portable bookmark envelope that both PoeXD and TFT Trade Extension can read: an unprefixed `Base64(JSON.stringify({ folders }))` share code, or the same JSON as a backup file. It contains only names, search endpoints, search type, game version, Auto or pinned league, folder structure, and approved `coverImageUrl` values. It never carries query criteria, realm hosts, accounts, runtime state, or timestamps. Legacy `poexd-bm1:` / `poexd-bm2:` codes are rejected. See ADR-0007.
_Avoid_: Full backup, Search Record export

**History Entry**:
A recency-ordered reference to a Search Record, refreshed whenever that search is used again.
_Avoid_: Search Record copy, history item

**Search Observation Session**:
The period during which Trade Assistance observes one open Trade page, from attachment until page teardown. It may span search and live modes but never retains Trade query criteria beyond what the canonical search ID already encodes.
_Avoid_: Search page controller, browsing session

**Preference**:
A durable user choice that changes Trade Assistance behavior or presentation. Preferences are either game-version-specific (`poe1` / `poe2`) or global across the extension (such as `theme` and `displayLocale`). It excludes transient pane state and retained Search Record or Bookmark data.
_Avoid_: Setting, configuration value

**LiveSearch Primary Page (User-facing: 線上搜尋主控台)**:
The per-game-version (`poe1` / `poe2`), extension-controlled singleton Trade tab that serves as both the authoritative runtime owner and console view owner for PoeXD LiveSearch of that game version. Its identity is owned authoritatively per game version by the Background coordinator across MV3 service worker lifecycles, allowing PoE 1 and PoE 2 consoles to coexist independently. Closing a console tab terminates the LiveSearch session for that game version. In user-facing UI, it is always presented using the active Display Locale's console terminology (e.g.,「線上搜尋主控台」in `zh-TW`, never exposing internal `Primary` terminology), fixes its browser tab title (`document.title`) to the localized console title, switches the PoeXD Sidebar into a dedicated LiveSearch mode with dedicated「搜尋連線」and「主控台設定」navigation (plus a「＋ 新增連線 / ＋ 暫時搜尋」action, syncing Sidebar header `activeTabName` with the active navigation view), and applies Result-Only Presentation on the official host page (hiding and blocking non-result official header, navigation, search panel, and footer while preserving `.results` and required official overlay/tooltip containers). Its default console presentation prioritizes「搜尋連線」by focusing directly on two operational connection sections — **「本次連線」(`sessionConnections`)** (connections added/enabled during the current console session, where pausing an active connection via its single status-action button keeps it in「本次連線」and in `LiveSearch Resume Plan` for quick re-enabling, and removing it is an explicit action via `⋯ -> 從本次連線移除`, `移除已停止的連線`, or dragging to `DragTrashZone`) and **「上次連線」(`previousConnections`)** (connections from the previous session's `LiveSearch Resume Plan` for the current `selectedLeague` that have not yet been added to「本次連線」, supporting single-item enable, single-item removal, drag-to-trash removal, batch restore, and league-scoped clearing) — rather than projecting the entire un-enabled Bookmark Folder Tree on the main console view. Connections can be added via Normal Page background push-to-console actions (「送入線上搜尋主控台」on Bookmark rows/folders and「送入主控台」in the official search controls, delivered in the background without stealing focus) or via the Console's lightweight two-tab「＋ 新增連線」dialog (Tab 1:「從書籤挑選」multi-select bookmark/folder picker; Tab 2:「輸入搜尋網址」URL input with auto-derived name). It renders locked league, connection health (`監聽` / `異常` counts), and `/fetch` API health (`API ● 正常` / `API ◐ 等待 Xs`) as a compact operational status header, shows no technical diagnostics (the official result header reflects the retained, filter-aware result count instead), exposes the result display cap as a durable versioned Preference (`PreferencesModule` SSOT: `liveSearchMaxDisplayedResults`), and keeps Rate detail expansion and section collapse as transient session UI state.
_Avoid_: LiveSearch window, background tab, secondary view, live search crawler, user-visible "Primary" label

**Temporary Search (User-facing: 暫時搜尋)**:
A console page-session-only search source that exists in the LiveSearch Primary Page's in-memory state (entered via the「輸入搜尋網址」tab of the「＋ 新增連線」dialog or pushed from a Normal Page official search form via「送入主控台」). When enabled in the console, its canonical identity and optional display metadata (`name`, `url`, `coverImageUrl`) are recorded in the `LiveSearch Resume Plan` so it can appear in「上次連線」on the next console launch. When a Bookmark connection is active and its source Bookmark is deleted or modified to a different canonical URL in another tab, the active runtime connection seamlessly falls back to a Temporary Search with origin provenance without interrupting or recreating the WebSocket. When a durable Bookmark is added with matching canonical search identity, source ownership is promoted from Temporary Search to Bookmark without reconnecting. Bookmark always takes presentation precedence over Temporary Search for identical canonical search identity, guaranteeing that every active Runtime subscription has exactly one visible presentation owner in the console.
_Avoid_: Custom URL source, 自訂搜尋, 自訂網址, persistent temporary search

**LiveSearch Resume Plan**:
A durable, per-game-version (`poe1` / `poe2`) activation intent for search connections enabled in the LiveSearch Primary Page (supporting both Bookmark-backed and non-bookmark/Temporary Search connections). It supports multi-league coexistence per game version, recording which searches the user previously intended to keep in the console across reloads and browser restarts, and projecting any not-yet-enabled items for the current `selectedLeague` into the Console's「上次連線」(`previousConnections`) section. Canonical identity (`gameVersion`, `league`, `searchId`) remains the permanent authority (joined dynamically with authoritative Bookmarks when matching, or using optional stored metadata `name`, `url`, `coverImageUrl` for non-bookmark connections). It is strictly separated from runtime lifecycle: Resume Plan != Runtime state, Resume Plan is independent retained domain data stored in `chrome.storage.local` (isolated by game version), and Resume mode (`off` [清理: clears previous connections for current league on startup] | `prompt` [保留: keeps previous connections in「上次連線」] | `auto` [自動恢復: auto-enables on startup], defaulting to `prompt`) is a durable Preference (`liveSearchResumeMode`). Storage failures (`unloaded` / `error`) never create fake empty plans, never prune, and never block runtime operation. Batch restore outcomes (including mixed-league atomic rejections) are always presented to the user.
_Avoid_: Runtime snapshot, session restore, subscription persistence, WebSocket persistence

**Console Sound Notification (User-facing: 通知音效)**:
The sound the LiveSearch Primary Page plays when one of its active connections receives a new result. PoeXD decides when it plays (ADR-0016): on result-token acceptance, before `/fetch`, coalescing bursts from any number of connections into one sound. It plays the official page's own `<audio>` element, syncing sound selection (built-in or custom audio) and volume (0–100) directly with the official site's `lscache-tradewoop` / `lscache-trade2woop` entry from the console settings pane, while the version-specific Preference `liveSearchSoundEnabled` turns it off for the console only. When the browser blocks playback because the console has not been interacted with, the console says so instead of failing silently.
_Avoid_: woop, official notify, alert sound, desktop notification (a separate feature)

**Trade Page Role**:
The authoritative, extension-assigned identity of a Trade tab (`normal` | `live-search-primary`). It is independent of official web route state (`TradePageMode`: `search` | `live`) and is determined exclusively by per-version Background ownership rather than URL paths, query parameters, DOM flags, or page state.
_Avoid_: Tab mode, page state, route mode

**Display Locale (User-facing: 語言 / Language)**:
The single global Preference (`displayLocale`, migrated from legacy per-version `affixDisplayLocale`) that controls both the extension's UI language and the language in which game data (affix templates, tier descriptions, item names, item categories, affinity labels, non-stat filter labels, Search Preview, and Criteria Overlay labels) are presented. See ADR-0011. It defaults to **Auto** (follows a non-English official Trade page locale when on a Trade page, or falls back to a supported browser locale such as `zh-TW` / `zh-CN` — including secondary entries in `navigator.languages` when the primary browser UI is non-Chinese — when on an English Trade page or standalone extension page, otherwise `en`) or can be pinned to any of the 11 supported locales (`en`, `zh-TW`, `zh-CN`, `ja`, `ko`, `ru`, `de`, `fr`, `es`, `pt`, `th`). Extension UI copy is localized in `zh-TW`, `zh-CN`, and `en` (when Display Locale resolves to one of the other 8 affix locales, `auto` prefers a `zh-TW` / `zh-CN` browser locale before falling back to `en`, while an explicitly pinned affix locale falls back directly to `en`), while already-saved user data (such as Bookmark names and Stat Group Template names) is never mutated. When an affix has no official Trade stat ID and must be typed into the official search box, the query always uses the **Page Locale** (the language of the current Trade page itself) rather than the Display Locale; when the Display Locale is Traditional or Simplified Chinese, English affix text remains searchable alongside Chinese.
_Avoid_: Affix Display Locale, split UI and affix language settings, realm language, hardcoded zh-TW

**Market Translation (User-facing: 市集漢化)**:
Showing the official international English Trade site (`www.pathofexile.com`, PoE 1 and PoE 2) in Traditional or Simplified Chinese: its interface strings, dropdowns, filters and result rows, using the wording of the Taiwan or China realm respectively (and, when the optional `https://pobb.in/*` permission is granted, also translating `pobb.in` share pages using the same official data shards). It is a global on/off Preference (`marketTranslation`, plus `marketTranslationBilingual` for `中文 (English)` dropdown labels and `marketTranslationResultBilingual` for muted English subtitles under translated result mods) whose target is the resolved Display Locale, and it is active only when that is `zh-TW` or `zh-CN`. It is display-only: values sent to the Trade API (`type`, `name`, stat and option ids) and everything our own features read are never changed, and entries without a confident translation stay in English. It never runs on localized realms. All text comes from official realm data generated at build time or refreshed in the background from official realm endpoints (6-hour cache TTL), never from hand-written dictionaries. See ADR-0012.
_Avoid_: Page translation, machine translation, localized realm, 中文化 of our own UI (that is Display Locale)

**Live Trade Data (即時市集資料)**:
The Trade filter labels (groups, fields, options) and stat Trade Wording, including pseudo stats, that the current official Trade page has itself loaded, read from the page without any extra request. It is used ahead of the bundled Trade shards, per id, only when the Display Locale equals the Page Locale and Market Translation is not active; otherwise, on extension pages, before the page's data is read, or when reading fails, the bundled shards are used. While Market Translation is active the page's own data is never used; the sidebar instead overlays the target realm's filter labels and Trade Wording from the Market Translation background cache (ADR-0012), under the same per-id, labels-only rules. It only replaces displayed text, never ids or values sent to the Trade API, is validated as untrusted input, and lives in memory for one Search Observation Session. Game data (tiers, Game Wording, result-row labels, item names) is never Live Trade Data. See ADR-0014.
_Avoid_: Remote data, runtime CDN data, cached filters

**Pinned Item (User-facing: 釘選物品)**:
A snapshot of one Trade result that the user pinned from a result row (search page, live search, or the LiveSearch Primary Page) to review later in its own Sidebar pane. It is a result, not a Search Record: it holds a whitelisted copy of the item JSON and listing (price, seller account, whisper text, listing time, instant buyout or not), plus the realm, league, source search ID and page locale it was pinned from. It never holds Trade query criteria or the time-limited `hideout_token` / `whisper_token`. It is game-version-specific, lives only on the local device (at most 50 per game version; new pins are rejected at the limit), is never part of Bookmark Transfer, and is written only by the Background. When Travel to Hideout confirms a listing is sold or removed, `sold: true` is persisted on the snapshot (keeping Travel to Hideout disabled across reloads while keeping comparison, PoB copy, and source link available until re-pinned or cleared). Whisper and Travel to Hideout only work on the realm it was pinned from. Travel to Hideout fetches a fresh token from the source search when the user clicks, distinguishing token refresh from sending the teleport request. Its Sidebar card is a sanitized snapshot of the official result card taken at pin time (older pins fall back to a card drawn from the item JSON); English cards are translated by Market Translation like result rows. In the pane a pin is a compact row (40px icon, name in its rarity colour, age and cross-league/realm tags when applicable, price with the currency icon captured at pin time) whose hover actions (travel/whisper, open source, and `⋯` menu containing PoB copy and unpin) appear on hover and whose row switches into the expanded card on click (replacing the collapsed summary row with a two-column header — framed 88px icon on the left and price, converted price with currency icon when `enablePriceComparison` is enabled, gold fee with coin icon when present, pinned time, seller/age, collapse button, and full action bar on the right — above the official popup card with inline centered mods and left-aligned mod numerical ranges). The user orders the pane by dragging rows, filters them with search, and unpins by dragging a row to the `DragTrashZone`, from the row menu, or via the clear menu (direct clear of sold items, confirmed clear of the visible league or all pins). See ADR-0017.
_Avoid_: Saved item, favorite, bookmark item

**Result Board (User-facing: 搜尋結果看板)**:
A Sidebar workspace over the results that one Trade search on a Normal Page (search mode) has retrieved, where the user filters, sorts and groups them (for example by seller) without changing the official result list. It belongs to exactly one search: starting a different search replaces its contents, and it keeps nothing beyond the page session. It covers only results already retrieved, at most the official cap of 100 per search, and says so when more matched. It can load further results on request, either the next batch or all remaining ones with visible progress and a way to stop, but never merely because the Sidebar was opened; loading more always goes through the official page's own "load more", so every board entry is also an official result row. Picking a board entry locates and highlights that row. It is reached from its own Sidebar pane and from a shortcut beside the official result count. It has two views: an item list (one compact row per result that expands into its card) and a seller list, whose purpose is buying several results in one hideout visit: one row per Seller, ordered by how many of the retrieved results they hold that are instant buyout, then by their converted total, filterable to sellers holding at least N such results, and offering a Stash Search Regex for the results the user picks from that Seller. A Seller can be hidden for the rest of the board's life; the board never keeps a lasting list of sellers. Results and Sellers the user has travelled to are marked as visited, and as sold when the official site reports the listing gone; these marks also end with the board. Keeping a result beyond the session is done by pinning it, which makes a Pinned Item. Price sorting, price filtering and converted totals exist only where prices can be converted to one currency; elsewhere totals are shown per currency (for example "2 div + 150 c"). Where conversion exists, individual results whose price cannot be converted sort last and are left out of converted totals, which say how many were left out. A Seller row shows their price range and the total of the results the user has picked.
_Avoid_: Dashboard, kanban, result cache, saved results

**Seller (User-facing: 賣家)**:
The account that listed a Trade result, shown with its most recent character name. Results listed by different characters of one account belong to one Seller. Most results today are **instant buyout**: the buyer travels to the Seller's hideout and buys without the Seller's involvement. For results that can only be whispered for, the Seller's online or AFK status is shown as information only.
_Avoid_: Character, merchant, shop, tradable

**Stash Search Regex (User-facing: 倉庫搜尋 regex)**:
Text to paste into the in-game stash search while visiting one Seller's hideout, so that all the results the user chose to buy from that Seller light up at once, and as little else as possible. It is written from each result's own item data, in the language the realm's Trade site returned it in, never in the Display Locale or the Market Translation language. It includes the listed price, written the way the Trade site writes it, because a Seller's stash holds many items the board never saw and the price narrows the match against them. It is only guaranteed to tell the chosen results apart from that Seller's other retrieved results, since the rest of their stash is unknown, and the user is told so. When it would exceed the game's search length limit for that game version it is split into several parts used one after another.
_Avoid_: Filter string, search string, item regex

**Trade Wording vs Game Wording (市集寫法／遊戲寫法)**:
Two ways the same stat is worded. **Trade Wording** is how the official Trade site words a stat id: exactly one wording per id, with the increased/reduced direction fixed per id by GGG (not derivable from stat descriptions and independent of the mod's actual sign), and identical in direction across realms when looked up by id. **Game Wording** is how a concrete mod reads in game, following its actual values. Affix selector stat labels, Trade filter rows and Market Translation dropdowns use Trade Wording (official realm `trade-stats.json`, then poexd-data `statTemplates`, which poexd-data derives by matching the English Trade text to a stat-description variant); tier rows, hybrid mod groups and result rows use Game Wording (poexd-data `tierTemplates`). Example: attribute requirement mods are all negative, so in game they read "15% reduced Attribute Requirements" while Trade words the stat "#% increased Attribute Requirements" and is searched with a negative value.
_Avoid_: Canonical text, positive form

**Legacy Wording (舊英文寫法)**:
An earlier English Game Wording of the same stat hash that GGG has since rewritten (for example 3.30 turned "#% increased Rarity of Items found" into "+#% to Item Rarity"). Item text exported before the change, such as Path of Building builds, still uses it. poexd-data publishes each hash's Legacy Wordings with the current wording they map to (`stat-aliases.json`), so the PoB shopping list translates old text to the current official translation. See ADR-0015.
_Avoid_: Old mod text, deprecated mods
